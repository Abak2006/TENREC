# Security

TENREC can change firewall rules and control processes, so the boundary between "observe" and "change" is deliberate.

## Trust boundaries

- **Webview → Rust.** The UI is treated as untrusted input:
  - Commands that change the system accept only action IDs created by the backend (`apply_actions`), or a PID/application ID that the backend resolves against its own latest sample (`prepare_process_action`, `prepare_app_block`).
  - Requests are size-limited.
  - A strict Content Security Policy is set in `tauri.conf.json`: no remote scripts, and IPC only.
- **Rust → netsh / PowerShell.** Every value on a command line is validated first (`protection/guard.rs`):
  - IPs must parse and be public.
  - Paths must be existing absolute files with no quotes.
  - Ports must be numeric, and the protocol must be TCP or UDP.
  - Rule names are generated by TENREC.
  - The only PowerShell invocation is a fixed script with no interpolated input.

## Safety rules for privileged actions

1. **Detection never changes anything.** Rules only produce incidents and proposed actions. Every change needs explicit approval in the review dialog. Disruptive actions are never pre-selected.
2. **Only TENREC's own firewall rules.** TENREC only creates and deletes firewall rules named `TENREC_RULE_<random>`. Deletion refuses any other name.
3. **Protected processes are refused.** Suspending or deprioritising core Windows and security processes (`csrss`, `lsass`, `svchost`, `dwm`, `explorer`, Defender, TENREC itself…) is refused. So is blocking `svchost`, `lsass`, `services`, or Defender by program.
4. **Private addresses are never blocked.** IP blocks only accept public addresses, so a mistake cannot cut off your router, DNS server or LAN.
5. **Stale PIDs are left alone.** Process actions verify the process creation time before applying and before undoing.
6. **Everything is recorded and reversible.** Every applied change is stored with its undo data in SQLite and survives restarts. Every attempt, successful or not, is written to the audit log.
7. **Least privilege.** TENREC runs as a standard user by default. Firewall changes fail with a clear message unless the user starts it as administrator. There is no background service.

## Known limitations

- The heuristic rules are easy to evade and produce false positives. TENREC is not antivirus.
- Version-info company names are self-declared by each executable and are not Authenticode-verified.
- Release builds are not code-signed yet.

## Reporting

Please report vulnerabilities privately to the maintainers rather than in a public issue.
